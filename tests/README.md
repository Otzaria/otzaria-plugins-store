# בדיקות שחזור של חנות התוספים

```sh
npm ci --ignore-scripts
npx playwright install --with-deps --only-shell chromium
npm test
```

הבדיקות פותחות את `index.html` האמיתי ב־Chromium מקומי, עם הקובץ
`restore-state.js` ומילון התרגום. שרת HTTP מקומי מגיש רק קובצי מקור.
קריאות ה־SDK, הקטלוג, ההתקנות ותוצאות המעקב נשלטות ב־fixture, וכל בקשת
דפדפן לכתובת חיצונית חסומה. הבדיקות פועלות בתהליך יחיד ומוגבלות בזמן.
אפשר לבחור בינארי מקומי קיים באמצעות `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

## מה נבדק

- יצירת מסמך חדש מהמצב שנשמר: בית, כל התוספים, קטגוריה, חיפוש, תגית,
  הסתרת מותקנים, סטטוס, מיון, מזהה דף פרטים וגלילה אנכית ב־`app-content`.
- טעינת קטלוג עדכני לפני אימות מזהים ושחזור, קדימות ההעדפה של המופע על
  האחסון המשותף, והעדפת פעולת משתמש או שינוי שפה על תשובה ישנה.
- קטלוג, קטגוריה וחיפוש שמגיעים בסדר שונה; מזהים שנמחקו; מצב פגום,
  גדול מדי או מגרסה עתידית. המצב מוגבל ל־8 KiB ולשדות תצוגה מוגדרים.
- API אופציונלי שאינו קיים במארח ישן, כתיבה שנדחתה, וניקוי שלא אושר.
  אישור שמירה הוא רק `{ success: true, data: true }`.
- שמירה ממתינה מול תחילת התקנה, יצירת טוקן, בקשת התקנה, הפסקות בין
  קריאות polling, התקנות חופפות, עדכון כל התוספים, כישלון וביטול.
- מצב שאין בו דיווח סיום אמין: טוקן חסר, דיווח חסר, timeout או תשובת RPC
  שאבדה. במקרה כזה המסמך הנוכחי ממשיך להיות פטור מפינוי אוטומטי עד
  לסגירתו או לטעינתו מחדש, גם אם המשתמש ממשיך לנווט בחנות.

`plugin.requestInstall` מאשר שיגור של בקשת התקנה. הדיווח בשרת הוא שמאשר
את סיומה. ההגנה לכן מקיפה את הפעולה כולה ואת האצווה, וממתינה לאישור
`plugin.setRestoreState({ state: null })` לפני יצירת טוקן או התחלת התקנה.
שמירה רגילה ממתינה לסיום כל הפעולות. טוקנים, הקטלוג ותהליכי התקנה אינם
נכללים במצב השחזור; לא מתבצעת התקנה אוטומטית בעקבות שחזור.

## גבולות האימות

אלה בדיקות דפדפן של קוד התוסף. פינוי WebView מתוך יישום אוצריא, צריכת
RAM בפועל וזמן חזרה ללשונית מחייבים בדיקה ביישום Native בכל פלטפורמה
נתמכת. נדרשת גם בדיקת התקנה אמיתית מול המארח והשרת בתרחיש שבו המארח
מנסה לפנות לשונית במהלך הפסקת polling. ה־fixture אינו הוכחה לביצועיהם.

חלוניות עדכון, lightbox, הודעות זמניות וגלילה אופקית בשורות הבית אינן
חלק מהמצב הנשמר. אין כאן שינוי לסף הפינוי, לסקריפט הרקע או לגרסת הפרסום.
קובצי הבדיקה ותלויות npm מוחרגים מחבילת התוסף באמצעות `.otzignore`.
תהליך `Publish plugin` הקיים נשמר. ה־CI הנוסף מאמת ואורז עם
`publish: false`, ומריץ את הבדיקות.

## תאימות גרסאות

הבנייה החדשה דורשת אוצריא **0.9.98.1**, שבה נוסף
`plugin.setRestoreState`. הקריאה מפורשת ונבדקת גם ב־validator הרשמי;
`minAppVersion` הועלה בהתאם לחוזה שלו. גרסת התוסף עצמה לא הועלתה ולא
מתבצע כאן פרסום לחנות. בחירת גרסת תוסף קודמת התואמת ליישום ישן נשענת
על מנגנון `versions` / `selectBestVersion` הקיים בחנות.

הטיפול בדחייה של API השמירה נשמר גם בזמן ריצה: אם לא התקבלה מעולם
שמירה והמארח אינו מכיר את המתודה, התצוגה וההתקנה ממשיכות לפעול עם
הפטור הקיים מפינוי. בדיקות ה־fixture למסלול הזה אינן מבטלות את רצפת
התאימות של קובץ המניפסט.
